# near-api

FastAPI backend runtime skeleton for NEAR Intelligence (NI-002).

- Source: `src/near_api/` (src layout, installed editable by `uv sync --project apps/api --frozen`).
- Configuration: root `.env` created from [.env.example](../../.env.example); loading is explicit and injected environment variables win. `/health` returns 503 with a readable message when required configuration is missing.
- Nothing else starts on boot: no collectors, no models, no ingestion, no scheduler.
- Runbook: [root README](../../README.md), [dependencies](../../docs/DEPENDENCIES.md), [deployment](../../docs/DEPLOYMENT.md).
- Identity-only PostgreSQL/Alembic foundation and real disposable-cluster checks: [database setup](../../docs/DATABASE_SETUP.md). Migrations are explicit; startup opens no database connection.
- Bearer-JWT verification, principal bootstrap and the `get_principal` dependency for private routes: `src/near_api/auth/` (NI-018; [authentication security](../../docs/AUTHENTICATION_SECURITY.md)). The runtime engine for authenticated routes is built lazily from `DATABASE_URL`.
- Request-scoped ownership: `src/near_api/db/security.py` (verified-owner helpers, standardized `ResourceNotFound` 404, owner-scoped pagination) and `src/near_api/repositories/` (owner-scoped document chain access; NI-019; [database setup](../../docs/DATABASE_SETUP.md)). Private tables carry forced RLS with transaction-local identity; private queries always go through `db/security.principal_transaction`.
- Owner-scoped workspace home: `GET /api/home` in `src/near_api/workspace/` (NI-022; [API specification](../../docs/API_SPECIFICATION.md)). Recent documents are capped at 5 with owner-scoped totals from one `scoped_page` call; pending sections (recent_charts/recent_insights/indicators) serialize as documented empty arrays until NI-035/NI-046-047/NI-031-032 land. Private responses are `no-store`; errors are 401/403 through `get_principal` and the one generic `ResourceNotFound` 404.
- Immutable dataset staging and publication: `python -m near_api.datasets {stage,stage-from-import,validate,publish,show}` in `src/near_api/datasets/` (NI-028; [data pipeline](../../docs/DATA_PIPELINE.md), [database schema](../../docs/DATABASE_SCHEMA.md)). Canonical SHA-256 manifest hashing deduplicates identical semantic input; staging persists version/members/inputs/observations with validation in one advisory-locked transaction (committed status is `validated` or `rejected`); publication is the single approved-pointer transaction with the previous version retained; `stage-from-import` reads observations from re-verified NI-027 archive import batches offline. Operator role only (`near_operator` credential); no browser route exists for these verbs.
- Exact metric computations and the definition registry: `src/near_api/metrics/` (NI-029; [data pipeline](../../docs/DATA_PIPELINE.md), [metric catalog](../../docs/METRIC_CATALOG.md), [database schema](../../docs/DATABASE_SCHEMA.md)). The registered definition registry (`registry.py`) is immutable and versioned with deterministic UUIDs, appended into `app.metric_definitions` (migration 0005) idempotently with content verification; canonical event aggregation (`events.py`) deduplicates or quarantines by NEAR event identity, accepts only successful executions, excludes internal treasury hops and other-sender inflows, and matches payouts by the unique amount+receiver candidate within the recorded 300 s tolerance; the pure-Decimal formulas (`compute.py`) run in an exact 100-digit context, quantize stored values explicitly to the NUMERIC(78,30) scale while preserving the exact string in quality metadata, keep missing prices as missing (never zero) USD values, report unavailable revenue as null with reasons, never deduct purchases from supply, and emit the purchases/issuance ratio as an upper bound. `python -m near_api.metrics build --spec FILE --out-dir DIR` reads the saved aggregates read-only and writes prepared manifests for `datasets stage`; both emitted datasets reconcile with the saved summary totals exactly. Operator tooling only; no browser route exists.
- Versioned chart definition registry: `src/near_api/charts/` (NI-031; [chart system](../../docs/CHART_SYSTEM.md), [database schema](../../docs/DATABASE_SCHEMA.md)). Immutable `(chart_id, version)` definitions with deterministic UUIDs are appended into `app.chart_definitions`/`app.chart_metrics` (migration 0007) idempotently with content verification; each definition binds registered metric definition UUIDs with required/optional series roles and per-series units taken from the metric registry, and fully describes what renders (visualization type, fixed category, allowed ranges ≤ 366 days, closed supported-filter JSON Schema from approved source/recipient mappings, update frequency, source lineage, renderer version), so adding a supported definition needs no new page implementation. Only `available` charts are advertised as live: charts bound to gated metrics or awaiting a published model artifact are registered `unavailable` with the recorded OQ reason. Migration 0007 also adds the documented contract change binding `dataset_metrics.metric_definition_id` to the metric definition registry (staged members must resolve). Operator tooling only; routes and ChartView resolution are NI-032 scope.
- Public delivery APIs for metrics, chart views, datasets and sources: `GET /api/metrics[/{metric_id}[/series]]`, `GET /api/charts[/{chart_id}[/view]]`, `GET /api/data-sources[/{source_id}]` and `GET /api/datasets/{version_id}[/manifest]` in `src/near_api/{metrics,charts,datasets}/routes.py` over the shared service `src/near_api/datasets/delivery.py` (NI-032; [API specification](../../docs/API_SPECIFICATION.md), [data pipeline](../../docs/DATA_PIPELINE.md) stage 8, [chart system](../../docs/CHART_SYSTEM.md)). Public reads through the unprivileged `near_app` role with no authorization and no user-identifying input; every series/chart-view request resolves exactly one approved dataset version (explicit UUIDs 404 unless `approved`; `latest` resolves deterministically over `active_datasets` and is cached ≤60 s with the last good version retained on publication failure), responses carry decimal strings, per-point quality with reasons, UTC half-open periods and a `context_hash`; chart filters validate against the resolved version's closed allowlist, ambiguous dimension variants surface as explicit null/unavailable points (never averaged or picked), unavailable charts are never advertised as live, source projections and the sanitized manifest expose no provider endpoints, credentials or operator paths, and approved content is served with a bounded version-keyed cache plus `content_sha256` ETags.
- Canonical document schema, revision service and projections: `src/near_api/documents/` (NI-036; [editor specification](../../docs/EDITOR_SPECIFICATION.md), [API specification](../../docs/API_SPECIFICATION.md)). `POST /api/documents` creates the document plus its first empty immutable revision; `POST /api/documents/{id}/versions` saves a new revision under `If-Match` compare-and-set (409 with the current revision on mismatch, zero rows on any validation failure) and regenerates the block/insight/hypothesis/evidence projections (migration `0006_document_projections`) in the same transaction. LiveChart blocks, snapshot chart mode, `model_run` evidence targets and non-empty `observed_contexts` are typed reference gates until NI-031/NI-035/NI-054/NI-041-043 land.
- Document CRUD and version endpoints: `PATCH /api/documents/{id}` (rename; a title change creates a full new revision with byte-identical content, an unchanged title is a no-op), `DELETE /api/documents/{id}` (owner-checked CAS delete whose cascade removes the private versions/blocks/projections while shared scientific data stays), `GET /api/documents/{id}/versions` (newest-first over the unique revision order) and `GET /api/documents/{id}/versions/{version_id}` (compositional owner check) in `src/near_api/documents/` (NI-037; [API specification](../../docs/API_SPECIFICATION.md)). Every mutation requires `If-Match` (428 without it) and never overwrites on 409. `POST /api/documents` and the save route honor `Idempotency-Key: UUID` through `src/near_api/documents/idempotency.py` and the write-once `app.idempotency_records` store (migration `0009_idempotency_records`): the response snapshot is committed atomically with the write, so a repeated identical owner/route/body request replays the original result for 24h (timeout-after-commit) instead of duplicating a document or revision; the same key with a different body is 409 IDEMPOTENCY_CONFLICT and failed writes store nothing.
- Publication gate, offline verification and public model APIs: `python -m near_api.research {fit,diagnostics,verify,publish}` in `src/near_api/research/` and `GET /api/model-runs[/{run_id}[/manifest]]`, `GET /api/model-definitions[/{model_id}[/readiness]]` in `src/near_api/models/` (NI-054; [reproducibility](../../docs/REPRODUCIBILITY.md), [API specification](../../docs/API_SPECIFICATION.md), [database schema](../../docs/DATABASE_SCHEMA.md)). `research verify --bundle … --offline` checks a run bundle (local report directory or the served manifest bundle) against the full data/code/lock/config/design/result manifest set fail-closed — no network, no database, no re-fit — and prints the canonical artifact hashes an operator approval must bind. `research publish` verifies the same bundle and only then writes the immutable run into `app.model_runs` (migration `0010_model_runs`) with the `near_operator` credential: published-only by CHECK, write-once (no UPDATE/DELETE grant), content-derived `run_id` makes re-publication idempotent and a re-approval of the same content a conflict. The public routes are read-only `near_app` projections of published rows only (unpublished/rejected runs do not exist in the table and are the generic 404), served with immutable cache headers and the run-id ETag; the manifest endpoint serves the verified bundle verbatim so a reviewer can re-run `research verify --bundle` offline. The model package imports no research code: endpoint access can never trigger a fit or a provider call.
- Frozen document export representation: `src/near_api/exports/ir.py` + the typed `ExportIr` contracts in `src/near_api/schemas/export.py` (NI-056; [reproducibility](../../docs/REPRODUCIBILITY.md), [editor specification](../../docs/EDITOR_SPECIFICATION.md)). `build_export_ir(engine, principal, document_id, version_id)` translates one owned, acknowledged immutable revision into the complete deterministic export plan: revision metadata (title/author/revision date/content hash), a typed mapping of every P0 block (rich-text runs, headings, lists, fully resolved frozen chart views through the NI-043 historical resolver, data-table specs with exact decimal-string cells, insight/hypothesis/evidence/risk cards) and the deduplicated source/model-run/citation references. Every pin is re-verified fail-closed (typed `ExportIrError` with bounded details — a missing pinned artifact or unresolvable reference never substitutes current data), no latest pointer is consulted, no wall-clock field is added (double builds serialize identically), and the plan is built only while the revision is the document's acknowledged current version (a rename creates the next revision, so title and content always describe the same revision). Static chart assets (NI-057): `src/near_api/exports/charts.py` renders the plan's frozen chart views through the pinned Node SSR renderer subprocess (no shell, strict typed stdin, timeouts/size caps, verified renderer identity and per-asset SHA-256, safe UUID-derived asset names). Every returned SVG is re-scanned for script/remote-reference content before acceptance; a misbehaving renderer fails closed.

Markdown ZIP delivery (NI-058): `src/near_api/exports/service.py` (owner-scoped job store on `app.export_jobs`, migration `0012`), `routes.py` (POST/GET/GET-download under `/api/documents/{document_id}/exports/...`, all owner-checked compositionally; typed `queued/running/succeeded/failed/expired` lifecycle with read-time expiry), `markdown.py` + `bundle.py` (deterministic `research.md` + `assets/` + `manifest.json` ZIP with per-file SHA-256, plan identity and renderer identity) and `worker.py` — the operator CLI `python -m near_api.exports.worker --database-url <near_app> --operator-database-url <near_operator>` (lease claim `FOR UPDATE SKIP LOCKED`, two-attempt cap, typed failures, `--sweep` TTL cleanup). The worker renders only from the frozen plan bytes stored at creation, so late edits never change a bundle. The HTTP contracts are registered in the generated client (`packages/shared-types`).

- Common schemas, sanitized errors and generated TypeScript: [API contract](../../docs/API_CONTRACT.md). `/openapi.json` is read-only and generation runs offline.
