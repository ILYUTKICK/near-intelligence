## Как это влияет на тезис

Подтверждён узкий факт: NEAR поступал из `intents.near` на исследуемые кошельки. Пока не доказаны происхождение всей суммы из комиссий конкретных свопов, размер удержанной выручки, покупки на рынке, сжигание либо постоянная блокировка токенов. Название кошелька `buybacks` этих выводов не заменяет.

Один день нельзя механически годовать: поступления могут быть накопленными выводами за другой период. До сверки временных окон нельзя делить эти суммы на объём свопов данного дня и называть результат take rate.

2. Проверить полноту выбранного дня: диапазоны блоков/времени, задержки загрузки и пропуски. При необходимости повторить выгрузку после стабилизации данных.
3. Ключ «NEAR thesis research — Explorer» создан после явного подтверждения пользователя 3 ноября 2026. Тип Explorer, статус valid / Auto-approved, срок до 3 ноября 2027. Сам JWT в исследовательских файлах не сохраняется. Доступ подтверждён: первый запрос вернул HTTP 200, 20 записей; время выгрузки 2026-11-03 11:38 UTC. Первоначальный сборщик (теперь scripts/fetch_explorer_probe.py) получил 20 записей за пилотный период и сохранил ответ и метаданные без ключа. Официальный playground указывает api.example.com; ключ в него не вводился. Прямой запрос из среды команд остановился на DNS, а управление приложением Terminal заблокировано инструментом. Пользователь выполнил первый ручной запуск скрипта.
4. Через `/api/v0/transactions` выгрузить полный день 1Click с пагинацией, всеми нужными статусами, небольшим перекрытием границ и дедупликацией по составному ключу. Соблюдать лимит 1 запрос / 5 секунд. Сохранить время выгрузки и параметры. Этот API покрывает 1Click, а не весь Intents.
5. Выбрать 10–20 разных свопов и связать `nearTxHashes` / intent hashes с receipts, результатами и FT events. Дать каждому соответствию статус: доказано / неоднозначно / не найдено. Не считать `appFees` фактическим доходом протокола, а разность входной и выходной USD-суммы — чистой комиссией.
6. Связать сбор комиссий, вывод накопленных средств и поступления на кошельки. Отдельно подтвердить покупку NEAR и дальнейшее использование. Если связи не восстанавливаются, явно зафиксировать предел воспроизводимости.

Критерий готовности этапа: воспроизводимая цепочка «своп → исполнение → начисленная комиссия → получатель → дальнейшее движение», либо документированный пробел на конкретном переходе. После этого расширять период до 30/90 дней и сравнивать рост бизнеса с экономическим эффектом для токена.

## Explorer: результат первого запроса

Первый запрос с явным включением всех шести статусов вернул 20 записей, все `PENDING_DEPOSIT`, без `nearTxHashes`. Их `createdAt` — от 2026-11-02T23:59:58.648Z до 2026-11-02T23:59:59.986Z. Это ограниченная первая страница у конца дня, а не случайная выборка.

Проверка показала работоспособность авторизации и наличие нужных полей. Она не дала исполненных свопов для on-chain сверки. Нельзя использовать число таких записей как число исполненных операций, а их долю на этой странице — как дневную долю незавершённых заявок. Статус наблюдается на момент выгрузки; исторический статус на момент создания не восстановлен.

Скрипт `scripts/fetch_explorer_probe.py` сохраняет логику первого запроса. Обновлённый `scripts/fetch_explorer.py` подготовлен для следующего ручного запуска: до 20 SUCCESS из каждого шестичасового окна и до 20 записей для FAILED, REFUNDED, PROCESSING, INCOMPLETE_DEPOSIT. Между запросами выдерживается 5,2 секунды. Это диагностическая выборка до 160 записей, не полная дневная выгрузка и не оценка долей статусов. Все ответы сохраняются отдельно, ключ — только в памяти процесса. Обновлённый сборщик проверен на синтаксис, сетевой запуск ещё не выполнен.
