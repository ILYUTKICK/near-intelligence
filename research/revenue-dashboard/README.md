# Как устроен revenue.near.org: проверка публичной части

Дата: 3 ноября 2026. Проверялись публичный HTML, серверные данные страницы и загружаемые клиентские JavaScript-файлы. Закрытый серверный код и внутренние API сайта недоступны в этой проверке.

## Что подтверждено непосредственно

1. Сервер отдаёт Next.js HTML вместе с готовыми данными React Flight. Из ответа извлечены ряды для volume, fees, net revenue, TVL, emissions, capture split и таблица кошельков. Это сохранённые данные, предоставленные сайтом, а не независимо верифицированные нами метрики.
2. Браузерные компоненты строят графики из переданных массивов. Для EfficiencyMetrics клиентский код группирует volume/fees по месяцам и считает fees / volume, revenue / volume и revenue / fees. Первые две метрики отображаются в bps. При выбранных 7D/30D эти компоненты помечаются Showing 90D и используют последние три месячные точки.
3. Разбивка CaptureSplit приходит уже рассчитанной: pp_fe_d30, pp_b2b_d30, pp_qi_d30 и аналогичные поля для других окон. На снимке их сумма — 38,88070206145177%; отображаемые доли округлены до 24,0%, 11,3%, 3,5%. Браузер не восстанавливает эти три категории из блокчейна.
4. В полученных дневных рядах volume/fees/TVL последняя дата — 2 ноября. Само заявление real-time не устанавливает точный график обновления серверных источников.
5. В FAQ сайт называет on-chain источники, включая контракт Intents. Полных исходных SQL, upstream URL, определения пользователя и всех правил атрибуции в проверенной клиентской части не найдено. В footer есть Figures shown are illustrative.

## Связанная публичная SQL-методика

Публичный адаптер DefiLlama для NEAR Intents описывает методику, которая сопоставляется с revenue.near.org:

- Gross fees: Dune datasets dune.near.dataset_near_intents_protocol_fees и dune.near.dataset_near_intents_fees.
- Captured revenue: поступления NEAR и wrap.near на три кошелька fefundsadmin.sputnik-dao.near, 1csfundsadmin.sputnik-dao.near, buybacks.multisignature.near. Внутренние переводы между ними исключаются.
- Адаптер ссылается на Dune queries 6162763, 6740088 и 6732239. Полный SQL этих страниц Dune в этой проверке не получен; SQL самого адаптера открыт.
- В комментарии адаптера отдельно указано: точная разбивка по потокам официального сайта является backend-логикой и не воспроизводится только по on-chain данным.

Это первичный источник методики самого адаптера. Он не доказывает, что текущий сервер revenue.near.org вызывает именно этот код или эти API при каждом открытии страницы. Верификация зависимостей серверной части сайта остаётся отдельной задачей.

## Как читать для инвестиционного исследования

Объём обменов, все комиссии, удержанная выручка, покупки NEAR, остаток кошелька и уничтожение предложения — отдельные величины. Wallet Breakdown подписан All-time; без проверки его методики нельзя заменять им живой RPC-баланс. В cumulative chart используется отдельный набор gross-fees-показателей, а в net revenue — отдельный месячный ряд; периоды и определения нужно согласовать перед сравнением.

Заявление в шапке о постоянном удалении токенов из обращения не является on-chain доказательством сжигания. В собственном FAQ сайта продуктовая выручка описана как средства, которые могут использоваться для buybacks, locking/staking и иных подходов. Это требует самостоятельной сверки фактического использования.

## Файлы

- index.html, rsc.txt — исходный ответ и извлечённые серверные данные.
- assets.json, *.js — публичные клиентские файлы, не запускались локально.
- efficiency.json — данные трёх графиков эффективности.
- capture_split.json — рассчитанные сервером доли.
- wallets.json — таблица потоков по кошелькам, как её передал сайт.
- revenue_charts.json, cumulative_chart.json — данные графиков.
- faq.json — ответы FAQ.
- inspection.json — выводы, границы проверки и контрольные суммы.
