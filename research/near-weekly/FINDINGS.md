## Как исключён повторный учёт

Учетная основа — только NEP-245 mt_mint / mt_transfer / mt_burn в успешных receipts intents.near. DIP4 token_diff, native_withdraw и нативные TRANSFER служат для интерпретации и сверки; они не добавляются повторно к тем же движениям.

Событие mt_burn уменьшает внутреннее представление актива при выводе из Intents. В этой цепочке оно сопровождается передачей NEAR получателю; считать его сжиганием предложения NEAR нельзя.

Внутренние переводы между счетами нашего набора выделяются отдельным признаком и должны давать нулевой суммарный net. В фактически полученном ledger таких переводов между выбранными 206 счетами не обнаружено. Переводы от других внутренних пользователей Intents остаются внешними относительно нашей исследовательской границы; «внешний» здесь не означает другую блокчейн-сеть и не доказывает комиссионный доход.

Валовые зачисления wrap.near без собственного token_diff в том же receipt составили примерно 70 233,4409 NEAR; в receipts с собственным token_diff — 25 083,1548 NEAR. Это категории исполнения, а не готовая разбивка на комиссионную выручку и покупки. Возможны сбор комиссий уже в NEAR, возвраты, накопленные остатки и конвертация средств вне нашего набора счетов.

## Пять неподтверждённых хешей API

Случаи S01/S03/S07/S16/S17 сохранены в data/independent_trace_audit.json. По всем указанным для них nearTxHashes независимо получена 21 транзакция из публичного Transactions API FastNear. В этих трассировках нет неразрешённых дочерних receipt IDs и нет Failure outcomes. Подтвердился один из двух API intentHashes для каждого случая.

Те же пять хешей не найдены в индексированных логах intents.near за 20 октября–3 ноября. Это воспроизводимое несоответствие полей API наблюдаемым исполнениям в исследованной области, но его причина не установлена. Полнота дерева конкретной транзакции не доказывает полноту списка транзакций, предоставленного Explorer. Эти случаи не называем неуспешными пользовательскими свопами и не используем для оценки failure rate.

- scripts/rpc_snapshots.py — ограниченный возобновляемый сбор, останавливается при HTTP 429.
- scripts/complete_public.py — последовательное продолжение с соблюдением Retry-After и обновлением отчёта.

## Первичные источники методики

[Verifier Contract](https://docs.near-intents.org/integration/verifier-contract/introduction) описывает внутренний ledger Intents. [NEP-245](https://github.com/near/NEPs/blob/master/neps/nep-0245.md) задаёт multi-token события и balance views. [NEAR RPC](https://docs.near.org/api/rpc/contracts) позволяет читать состояние на block_id; [список RPC](https://docs.near.org/api/rpc/providers) предупреждает об ограничениях публичного архива. [FastNear Transactions](https://docs.fastnear.com/tx/transactions) — второй источник трассировок.

Документация и прочитанный текущий исходный код использовались для выбора интерфейсов. Совпадение развёрнутого исторического WASM с текущим исходным кодом не аудировалось. Числовые выводы получены из сохранённых on-chain данных.

Состояние сборщика на момент обновления: `stopped_by_local_stop_file`.
