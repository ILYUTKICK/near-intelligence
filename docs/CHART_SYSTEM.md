# Canonical chart system

One versioned chart catalog and rendering adapter for public explorer, workspace, editor and exports. [Metrics](METRIC_CATALOG.md), [API](API_SPECIFICATION.md), [editor](EDITOR_SPECIFICATION.md).

## Definition versus instance versus observation

ChartDefinition is immutable and contains UUID version ID, stable chart_id slug, integer version, title, description, category, metric definition version IDs/series roles, visualization type, units, source lineage, expected update frequency, available ranges, supported filter JSON Schema and renderer version. Last-updated, data quality and actual date coverage belong to the resolved ChartView dataset, not a mutable definition.

SavedChart is a user's label/mode/selection and chart-definition version reference; it is not a copied chart implementation. A document chart block stores the same canonical definition reference plus selected context. ResolvedContext pins exact dataset/metric/renderer versions and selection hash. Snapshot (NI-044) adds an immutable owner-scoped object — pinned definition version, approved dataset version, canonical selection, calculation context and a deterministic content hash — created only by an explicit Freeze; no UPDATE path exists at any layer and the rendered/data `artifact_id` stays reserved. P0 document save pins already preserve reproducibility.

## Query/render contract

**NI-083 — long-history research (14 November 2026):** `intents-volume` and
`gross-fees` append version 2 definitions with a 730-day maximum. Existing
versions retain their original 366-day bound and identity. The public research
history uses source-qualified canonical approved views and a pinned long-history
dataset; its independently pinned purchase cohort keeps its own shorter dates.
The research page's server-calculated monthly/quarterly observed subtotals show
coverage and partial periods. Effective gross fee rate is the ratio of summed
fees to summed volume on matched dates, multiplied by 10,000 basis points; it
is not an average of daily rates or attributable protocol capture.

Browser Cartesian charts provide a linked timeline slider, Shift+wheel zoom,
drag panning and keyboard Zoom in/out/reset controls. The visible plot dates
are announced; zoom changes the viewport only, not the resolved period, exact
table, calculations or pins. Original decimal strings back tooltip/table values.
Long line charts hide idle symbols while keeping every observation. Static
exports use `interactions: false`, retain their original layout and omit zoom
controls. Recorded categorical thesis comparisons use the same ECharts runtime
with original claim strings and accessible text; they do not fabricate daily
observations or dataset identities.

ChartView resolves one approved prepared dataset containing required metric versions. `start/end/frequency/filters` are validated centrally; date range≤366 days initially. Default presets7/30/90 days relative to latest complete observation, not wall-clock if historical. A custom range outside coverage shows missing values, explains overlap and does not silently shrink. Supported filters include approved recipient/source mappings only; unknown options rejected. Currency switch chooses an actual alternative metric/calculation context.

**Multi-value comparison (NI-071, 2026-11-12):** a chart version's filter schema may mark a dimension `multi_value` (registered only from the immutable approved mappings in `near_api.charts.filter_registry`, which also declares per-dimension reconciliation identities and the NI-031 single-value enums). A selection carries a string for one value and a list for a comparison. One ChartView resolves **one compared series per selected value combination — server-side fan-out** (the recorded design decision: one coherent series table/legend/CSV instead of K parallel client queries). Canonical value order is the dimension's declared option order, never the request order; duplicates collapse once. Each fan-out series echoes its own exact-match single-value filters while the view-level selection and context hash capture the exact multi-selection. When a chart declares a reconcilable dimension (the verified universe of the bound metric — treasury `recipient`) and the selection covers the full declared universe, the per-value series must sum to the declared aggregate metric definition of the SAME dataset version at exact Decimal precision; a missing, non-exact or disagreeing period is replaced with explicit unavailable points carrying the reason. Cross-source (`source`) sums stay forbidden — that dimension is never `multi_value` and never reconcilable. No integrator/customer/collector classification exists. The compared series of one bound metric are distinguished in the legend and exact-value table by their selected filter values. The same shared controls (`features/charts/filters/`) render the checkbox comparison group on the chart detail and in the editor live-chart block edit (draft-local until Apply), and the URL selection round-trips the exact multi-selection through `filters` JSON (one selected value serializes as the bare string).

The version 2 detail page links explicitly to version 1 payout totals. Version 2 requires an approved dataset containing the per-recipient definition. Full-universe reconciliation also requires the version 1 aggregate in that same dataset. The renderer, both chart CSV paths and the PDF/ZIP captions retain the pinned selections. Legacy singleton selections serialize as strings to preserve their hashes.

Query keys include chart definition ID/version, dataset version, canonical selection and metric versions. Latest pointer resolution ≤60s cache; immutable versions cache by content hash. TanStack Query deduplicates identical public requests; private saved metadata no-store and cache cleared on logout. Never cache arbitrary user filters under a shared incomplete key.

Plot adapter receives normalized typed series, not provider responses. Use ECharts modular imports and SVG renderer where possible; no SSR import through browser globals. Lazy mount visible charts, debounce user range requests, cancel stale requests, preserve last successful plot with refreshing badge. Axis units/zero/truncation explicit; avoid dual axes unless a documented need and clear labels. No interpolation across missing flows; bounds displayed as bounds, not exact bars. Tooltips show date/time convention, unit, exact source value and estimate/bound label.

**Implemented renderer (NI-033, 2026-11-08):** `apps/web/src/features/charts/renderer/` is the one chart adapter for public and editor contexts. `option-builder.ts` is a pure typed builder from the generated `ChartViewResponse` to an ECharts option plus the accessible table model and summary; it imports no ECharts runtime and `buildChart(view, { interactions: false })` returns a JSON-safe option for the future Node static-export script (NI-057 reuses it, no second renderer). `ChartView.tsx` mounts ECharts lazily (IntersectionObserver with immediate fallback), debounces requests, cancels stale requests via AbortController and disposes instances on unmount/rebuild; the ECharts runtime is touched only in `chart-factory.ts` (modular `echarts/core`/`charts`/`components`/`features`/`renderers` entries, SVG renderer, `LegacyGridContainLabel`). Series semantics: the response contract carries no series role, so the renderer uses response order plus per-series `metric.unit` — series with different units never share a value axis and render as aligned panels (the registry "panels" behavior, generalized; no dual-axis implication); scatter pairs the first two series (registry binds x before y). Missing points stay `null` with `connectNulls: false`; bars/areas/lines are zero-anchored, scatter axes scale. Decimal strings are the only exact values (table + tooltip lookups render the original strings with grouping and bound prefixes); `Number` parsing happens only for plot coordinates and axis scale (ADR-019, tested), and a non-finite coordinate becomes a missing point. `RENDERER_VERSION` (`echarts-modular-svg@1`) is mirrored in `view-types.ts`, asserted equal to the apps/api registry constant by a test, and a definition pinned to another capability set is refused with an honest state instead of best-effort redrawn. The chart palette mirrors the DESIGN_SYSTEM tokens, with a test asserting the values still exist in `tokens.css`. Range presets come from the definition's bounded `available_ranges` (anchored to the selection end, not wall-clock); a custom date picker belongs to the chart detail page (NI-034). Indexed comparison with an explicitly chosen base (quantity-usd-sensitivity) needs contract support for a base parameter and is not silently approximated by this renderer.

## Interaction, provenance and accessibility

NI-075 uses the same chart-detail screen for public library and category URLs. Featured category charts resolve the latest approved view through ChartView. Their detail links carry the inspected dataset and range when that view resolves. Custom dates use the existing range validation in a keyboard-accessible dialog, and the URL selection round-trips through reload, sign-in continuation and saved-chart reopen (NI-078 verification). The versioned renderer palette stays stable for frozen export reproduction.

NI-078 uses the shared `ChartView` and `ChartFrame` on chart detail and Saved Charts cards. Detail groups range, filter, source and private actions in one wrapping toolbar. Its exact-value table stays visible without hover. A saved card shows its title, mode, period and filters once. The preview shows units, freshness, quality and the source drawer, with one keyboard-accessible disclosure for exact values, bounds and the summary. Each card loads its owned preview near the viewport and honors the session signal. Live previews resolve the latest approved data while preserving the last-opened dataset on the saved chart. Snapshot previews resolve the frozen pin.

Every frame includes definitions, sources and lineage, last observation/retrieval times, quality, mode, permitted actions and an equivalent data table. Keyboard range controls and point/table inspection must work; charts cannot require hover. Source drawer links metric formula and sanitized manifest. Enable ECharts ARIA component explicitly and add concise manual summary/table; [official ARIA guidance](https://echarts.apache.org/handbook/en/best-practices/aria/) does not imply fully keyboard-operable charts automatically.

States: loading skeleton; refreshing with last good; empty confirmed no observations; missing/incomplete coverage; stale historical/live; unavailable source; query validation error; reconstruction error for missing pinned artifact. Do not show zero in a KPI because plot array is empty.

Save Chart creates an owned instance. Add to Research validates destination and appends chart block using inspected immutable dataset version. Add Insight stores inspected context, not whatever chart happens to show on the next refresh. Refresh is an explicit latest-version query for a live view; snapshot/historical view offers “compare to latest” rather than overwriting.

## Static export and reproducibility

Implement a pure chart-option builder shared by browser and `apps/web/scripts/render-charts.mjs`. Node ECharts SSR renders bounded validated data into SVG without DOM/network/user HTML. Python export worker invokes this fixed renderer as a subprocess with typed JSON stdin, no shell; export image includes the Node package/lock. Include renderer version, dataset hash, selection/config hash and source references in manifest. If SVG is unsupported by a future PDF path, convert via a reviewed rasterizer without changing series data.

Archive chart-ready CSV/normalized series with each exported chart. Exact-data/hash reconstruction is required; pixel identity across platforms is not. Text/table renderers consume the same frozen series. Required tests: definition→query→render path reused across public/editor/export; gap/bounds/large-number handling; URL filters validation; table equality; source revision leaves old export unchanged; selected chart interactions do not break editor keyboard selection.

**Implemented renderer (NI-057, 2026-11-09):** `apps/web/scripts/render-charts.mjs` is the pinned Node ECharts SSR renderer for the frozen export evidence of one acknowledged revision (NI-056 IR). It reuses the NI-033 pure `buildChart(view, { interactions: false, animation: false })` builder — imported as TypeScript through Node's erasable-syntax type stripping plus a narrow extensionless-to-`.ts` resolution hook — so there is still exactly one rendering implementation; the ECharts runtime imports stay modular (ADR-019) and register the same component set as `chart-factory.ts`. Protocol: one strict JSON request on stdin (zod schema, `protocol_version` pinned, strict envelope, canonical-UUID chart ids, bounded width/height/charts/series/points; no URL/HTML/code field exists and unknown envelope keys are rejected) → one strict JSON response on stdout carrying per chart the SVG, a normalized CSV, their SHA-256 hashes and the series/point counts, plus the renderer identity (`near-export-chart-renderer@1`), echarts version, node version and the SHA-256 of the exact request bytes; any refusal exits non-zero with a typed `{error:{code,message,details}}` object. Determinism: same request bytes → byte-identical SVG/CSV; zrender's globally counter-derived style-class and clip-path identifiers (`zr3-cls-7`, `zr1-c0`) are rewritten to canonical first-appearance aliases inside `class`/`id`/`url(#…)`/`href="#…"` and `<style>` selectors, nothing else is touched. The CSV is lossless long format (`date,series_index,series,unit,value,value_kind,quality,quality_reasons`) with the exact decimal strings verbatim and RFC4180 quoting — missing points export empty with their recorded reason, never zero. Safety: the rendered SVG must pass static assertions (no `<script`/`<foreignObject`/`<image`, no `javascript:`, no remote `href`/`url(...)`, no `data:text/html`, no event-handler attribute) or the renderer fails closed; the script performs no fetch, spawn or eval (asserted by a source-scan test). The Python boundary `apps/api/src/near_api/exports/charts.py` invokes it with an ARGV list via `subprocess.run` (no shell anywhere), passes the payload on stdin, kills on timeout, enforces input/output/asset size caps, derives asset filenames only from canonical lowercase UUID block ids (`safe_chart_asset_name` — traversal, separators, shell metacharacters, control characters and non-canonical ids are typed refusals), re-verifies the response contract, hashes and chart-set coverage, re-scans every SVG with the same safety patterns and records the renderer script's SHA-256 in the typed `ChartRenderResult`. The node binary and renderer script path are operator environment configuration (`NEAR_CHART_RENDERER_NODE`/`NEAR_CHART_RENDERER_SCRIPT`), never caller input. CI: the boundary tests run in the api job (node + frozen workspace are provisioned there); the db suite is untouched (no database dependency).

## Saved instances — implemented NI-035

`/workspace/saved-charts` supports search, labels, confirmation before removal and reopening through the shared renderer. A resolved public chart offers Save Chart after sign-in; the mutation carries its inspected definition/dataset/range/filters with an idempotency key retained across retries. Saved views are explicitly live and label newly resolved datasets; document revision pins remain separate. NI-044 snapshot management lives at `/workspace/saved-charts/snapshots`: the chart detail (public explorer and saved-chart detail) offers Freeze of the inspected evidence triple, the snapshot list/detail show owner-scoped storage metadata (frozen instant, dataset pin, content hash) and render the frozen view in historical mode, Compare-to-live is an explicit read that never rewrites the snapshot, and a snapshot a saved chart references refuses deletion. The mobile workspace content column uses `min-w-0` so the chart/table cannot widen the whole page; the exact-value table keeps its own horizontal scroll. [Synthetic browser evidence](qa/ni035-saved-chart-mobile.jpg) was captured at 387px, with document width also 387px; physical-phone touch/keyboard testing remains NI-064 release validation.

NI-035 review correction: authenticated action attempts are keyed by the verified subject and inspected input. A same-subject focus check temporarily hides the action UI without destroying its retry key/result; an explicit auth-change/logout or a verified different subject discards the old attempt. Private list data is still cleared/revalidated on focus and account signals.

## Embedded working charts — implemented NI-042

Editor chart nodes reuse the same `ChartView` and exact-data table as the explorer. Their live policy requires explicit Refresh to adopt a new dataset. Default loads reconstruct the observed immutable pin. A pinned frame says Historical while the surrounding block says Live chart / saved observation. Range/filter drafts are local until explicitly applied and successfully resolved through the owner-scoped `/documents/{id}/chart-view`. Canonical server validation, query bounds and context hashes are shared with public delivery. Saving unchanged prose carries context JSON verbatim. NI-043 verifies submitted inspections and exposes the compatible approved dataset pointer as a working-view notice. Historical views and CSV reconstruct exclusively from the saved revision. NI-047 Add Insight freezes the inspected context in the new annotation. Snapshot management (NI-044) is implemented separately from revision pins: a saved chart in snapshot mode renders exactly its referenced frozen snapshot and compare-to-live is always an explicit additional read.

NI-064 desktop accessibility correction (13 November 2026): repeated editor chart exact-data regions retain their chart title, region role, keyboard focus and exact caption, and add the current human top-level research-block ordinal. Labels follow insert/move transactions; historical saved-chart regions carry the same context. This affects accessible names only, never chart definitions, financial values or frozen pins.


NI-080 default-date correction (13 November 2026): an implicit default on the
shared detail/featured-category screens resolves latest approved dataset coverage
before choosing its preset. A bounded bootstrap view discovers `dataset.end`;
when its dates differ from the bootstrap, the actual view is requested against
that immutable dataset ID, avoiding a latest-pointer race. Explicit date selections
are retained verbatim, including out-of-coverage selections; historical pinned
ranges keep their existing immutable coverage anchor. No date is shifted silently.

NI-080 initial-range correction (13 November 2026): when a detail or featured
chart has no explicit dates and resolves `latest`, one bounded view request
first discovers the approved dataset coverage. If the preset window differs,
the server fetches the preset anchored to that coverage end against the
immutable discovered dataset ID. Concurrent publication cannot switch the
second request's input. Explicit user dates, including an out-of-coverage
custom window, are never moved; pinned historical resolution is unchanged.
The same shared screen/helper serves public and workspace mounts.
